read · mutate · write, per touch

the round-trip the Slab deletes

v1 · Vec<Score> on a borsh account full round-trip
read
account bytes → borsh::deserialize → Vec<Score> on the heap
copy out
mutate
push / sort on the heap Vec
copy back
write
borsh::serialize(Vec<Score>) → account bytes
cost scales with the WHOLE list, every touch — even to read one entry
V2 · Slab tail the bytes stay put
read
byte cast → &[Score] view into the account — no copy
cast
mutate
write items in place through &mut [Score]
nothing
write
nothing to re-serialize — the bytes ARE the list
cost is the item(s) you touch, not the list length
The Slab does not make serialization faster. It removes the step — so list length stops being a per-touch price.
