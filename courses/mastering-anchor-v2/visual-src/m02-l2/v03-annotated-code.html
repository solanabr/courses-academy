tail items land at any offset

repr(packed) is the trap, not the remedy

01
BROKEN
#[repr(C)]
struct Score { player: Pubkey, points: u64 }
// used as a Slab TAIL item
the tail starts at no guaranteed alignment
It begins after the header + the len field, so &score.points would be a misaligned reference (UB) — the cast bails.
02
WORSE “FIX”
#[repr(packed)] // “just drop the padding”
struct Score { player: Pubkey, points: u64 }
// &score.points is now GUARANTEED misaligned
this creates the hazard
Packing removes padding, but taking &score.points is now guaranteed misaligned. It does not remove the problem — it locks it in.
03
FIX
#[derive(bytemuck::Pod, bytemuck::Zeroable)]
#[repr(C)]
struct Score { player: Pubkey, points: PodU64 }
// every field is [u8; N] — .get() / From
alignment 1, from any offset
Byte-array fields read correctly wherever the tail lands, so the byte cast is sound.
