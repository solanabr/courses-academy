re-verify on a schedule

The pin re-verification loop on a moving RC

trigger a
a build behaves differently than yesterday
re-run anchor --version
trigger b
release notes or a broken build say anchor-next moved
rebuild the RC
step 1
observe the real value
read the actual value — do not trust the date already in PINS.md
step 2
stamp today's date
write it in the verified column — even if the value did not change
a fresh date on an unchanged value still records that a human looked
repeats for the life of the RC
There is no cut release behind the RC, just a branch — the dated human check is the defense.
