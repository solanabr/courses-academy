isolate the field, don’t demote the account

The mixed account, split along the tier boundary

tier 1 · stays on the castCabinetCore
#[account]           // Pod, zero-copy
pub struct CabinetCore {    pub machine_key: [u8; 32],    // fixed  -> Pod    pub board: PodVec<Score, 10>, // MAX=10 -> Pod}
fixed + boundedBoth lengths are known at compile time — [u8; 32] is fixed, PodVec is capped at MAX = 10. Read by direct cast, no deserialize.
tier 2 · the isolated exceptionCabinetDescription
#[account(borsh)]    // the escape hatch
pub struct CabinetDescription {    pub text: String,   // unbounded -> borsh,                        //   deserialize on read}
the one unbounded fieldString has no compile-time length, so it — and only it — leaves tier 1. The exception is one field wide, not one account wide.
the payoff A handler that bumps only the board touches core, never description — zero deserialize cost, the hot path stays on the cast.
