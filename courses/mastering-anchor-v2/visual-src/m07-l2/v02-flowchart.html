the rhythm of this lesson

exploit first, patch second, prove it with the test

STEP 1
pick a surviving class
one of the seven the compiler will not catch for you
STEP 2
write an exploit test that SUCCEEDS
against the current code: drains / substitutes / over-withdraws
STEP 3
run it — it passes
the bug is real, not hypothetical. The attack is now a reproducible artifact.
exploit passes
STEP 4
name the exact missing guard
not "add validation" — the one assertion that is absent
STEP 5
add the guard
one constraint, or one checked op. Nothing bigger.
STEP 6
re-run: the exploit now FAILS
and the legitimate test still passes — the guard is tight, not blunt
guard proven
STEP 7
next class
seven times, once per surviving class
repeat, class by class
