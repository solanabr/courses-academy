attack 2 — duplicate-mutable

bare dup will not build on V2

#[derive(Accounts)] pub struct DrainPool { #[account(mut, dup)] // <-- bare `dup` pub reserve_a: InterfaceAccount<TokenAccount>, #[account(mut, dup)] pub reserve_b: InterfaceAccount<TokenAccount>, }
anchor build says exactly what to write instead
compiler output
error: duplicate-mutable opt-out must be written `unsafe(dup)` the MUT_MASK for this instruction marks reserve_a and reserve_b mutable; to intentionally allow the same account in both, write unsafe(dup).
the attack
Two mutable InterfaceAccount<TokenAccount> reserve slots, with the opt-out spelled dup — pass the same reserve twice and price the pool against itself.
what V2 does
It never reaches the runtime dup check. The attribute itself is rejected at build, and the error names the only spelling that would let it through.
the fix, named by the message
Change dup to unsafe(dup) — and only if the duplication is genuinely intended. The word unsafe is the point: it makes the intent reviewable.
