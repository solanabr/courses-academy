TS union → Rust enum, zero new design work

one design, two compilers, one holds the pen

TypeScript: discriminated union + switch
type ProbeResult = | { kind: "ok"; latencyMs: number } | { kind: "timeout"; afterMs: number } | { kind: "refused" }; switch (r.kind) { case "ok": return up(r.latencyMs); case "timeout": return degraded(r.afterMs); case "refused": return down(); default: return assertNever(r); }
=
same sum type
same closed set
Rust: enum + match
enum ProbeResult { Ok { latency_ms: u64 }, Timeout { after_ms: u64 }, Refused, } match r { Ok { latency_ms } => up(latency_ms), Timeout { after_ms } => degraded(after_ms), Refused => down(), // no default arm; E0004 names missing arms }
exhaustiveness is opt-in: the default arm must call assertNever
exhaustive by default, no opt-in needed
same sum type, same closed set, same refactor-checklist behavior
