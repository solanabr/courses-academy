optionality, fixed

the three shapes of an ActionPostResponse

minimal
{
  "type": "transaction",
  "transaction": "<base64>"
}
exactly two keys. this alone is a complete, valid response.
with message
{
  "type": "transaction",
  "transaction": "<base64>",
  "message": "Order placed: 1x WVL-045..."
}
added whole. shown to the user after signing — present only when you have one.
with chaining
{
  "type": "transaction",
  "transaction": "<base64>",
  "message": "Order placed: 1x WVL-045...",
  "links": {
    "next": { "type": "post", "href": "/api/actions/drop/thanks" }
  }
}
whole or not at all. the links block appears complete, or the key is absent — never null-padded.
no message input → no message key at all; same for links. only type and transaction are always present.
