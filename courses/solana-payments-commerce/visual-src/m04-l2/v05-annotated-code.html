a ledger row, and the invariant that makes it trustworthy

{
  "orderId": "ord-0088",
  "signature": "RealSig111...",
  "amountBaseUnits": "28000000",
  "mint": "EPjFWdd5AufqSSqeM2qN1xzybapC8G4wEGGkZwyTDt1v",
  "fulfilledAt": "2026-08-22T14:03:11.204Z"
}
orderId
the order this payment settled — from the on-chain memo, not the payload
signature
the idempotency key — unique per transaction, the reason a row can never duplicate
amountBaseUnits + mint
what the ORDER expected, verified on-chain — never what the webhook claimed; the bigint price serialized as a string because JSON has no bigint
fulfilledAt
server time of fulfillment — for reconciliation windows, next lesson
invariant row written only after fresh claim + passing verify — one row = one real payment
