the backoffice pipeline

five gates between a delivery and a ledger row

answer first — sync, inside the request
then work — async, per event, after the ack
in incoming POST array of Enhanced events
gate 1 auth header check the shared-secret bouncer
gate 2 shape filter is array · is TRANSFER · has signature
ack 200 — immediately ack first, then work
gate 3 claim signature in the registry
gate 4 resolve order via the on-chain memo
gate 5 verify on-chain the lesson-1 verifier
out ledger.record exactly one row per real payment
wrong secret → 401
duplicate → drop
no match → reject
fail → reject
transient error at gate 4 or 5 → release the claim — the next Helius retry heals it
