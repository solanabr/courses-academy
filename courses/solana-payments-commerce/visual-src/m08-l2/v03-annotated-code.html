one positional check carries the whole switch

how the runtime detects a nonce transaction

instruction 0 { // must be the FIRST instruction
  programAddress: 1111…1111 // System Program
  accounts: [
    [0] nonce account (writable)
    [1] SysvarRecentB1ockHashes111… (readonly)
    [2] nonce authority (signer) // merchant key
  ]
  data: [4, 0, 0, 0]
}
position zero
the runtime only checks index 0 — a nonce advance anywhere else is invisible to it
nonce account row
must be first in the account list, must be writable
data bytes
[4, 0, 0, 0] — the AdvanceNonceAccount discriminator
first instruction matches this shape
→ validate recentBlockhash against the stored nonce value
any other position or shape
→ recentBlockhash treated as a normal blockhash — and it expires in ~45s (150 blocks × 300ms target)
