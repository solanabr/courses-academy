anatomy of the stall QR’s payload

solana:https://localhost:3443/txreq?recipient=<merchant>&amount=0.15&reference=<base58 32-byte key>&label=Wavelength%20Records
1 · solana:scheme — tells the wallet this is a payment URL
2 · https linktransaction request — the server builds the tx
3 · /txreqyour endpoint from last lesson — unchanged interface (GET label/icon, POST {account})
4 · recipientignored by serverpassed along by the POS; payee is server config
5 · amountmerchant-keyed total, appended by the POS
6 · referencefresh per-sale key, appended by the POS; later polled via findReference
7 · labelstall name — display only
contrast: solana:<recipient> alone would be a transfer request — the wallet builds the transaction instead of your server.
