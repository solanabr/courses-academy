one fixture shape, five witness files

anatomy of a fixture

{ "name": "correct payment", "signature": "FixSigCorrectPayment111…",1 "expectedReason": "verified",2 "order": {3 "orderId": "ord-1024", … recipientAta, mint … "amountBaseUnits": "30000000" }, "transaction": {4 "meta": { "err": null, "preTokenBalances": [ … before … ], "postTokenBalances": [ … after … ] }, "instructions": [ …, { "program": "spl-memo", … } ] } }
1signature keys the fixture-backed fetchTransaction map. Unique per file, because the harness runs every fixture through one shared store.
2expectedReason is the single verdict the harness asserts verify() must return for this file.
3order is the ExpectedOrder from step 2. amountBaseUnits rides as a STRING because JSON has no bigint; the harness lifts it with BigInt() before calling verify.
4transaction is the getTransaction-shaped witness: meta.err, the pre/post token balance arrays, and the parsed instructions the memo check reads.
