the fork in the solana: scheme

Transfer request vs transaction request

Transfer request
solana:<recipient>?amount=...
Transaction request
solana:<https-link>
who builds the transaction
the customer's wallet
your server
what the URL carries
recipient, amount, spl-token, reference, label, memo
an opaque link (plus an order id you choose)
what it can express
one fixed transfer
anything your code can assemble: carts, coupons, dynamic memos
where pricing lives
in a customer-editable string
in your backend
tamper surface
every query parameter
none of the pricing: the URL holds no prices to edit
transaction requests move pricing server-side: the customer scans a link, never a price they can edit
