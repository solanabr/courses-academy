THE CONTEXT-ACCOUNT DANCE

one logical transfer, several transactions on the wire

tx 1..n verify proofs into context accounts each proof goes to the ZK ElGamal Proof Program → verified → written into a short-lived context state account
equality proof → context account
validity proof → context account
range proof → context account (typically alone in its tx)
why: the proofs exceed the 1,232-byte transaction envelope
tx n+1 the Transfer executes Token-2022 Transfer runs, referencing the equality, validity, and range context accounts instead of carrying the proofs inline
tx n+2 clean up close the context accounts and reclaim their rent — they only ever existed to smuggle the proofs past the size limit
future lane transaction format v1 (SIMD-0296 line, now carried by SIMD-0385) is designed to collapse this to ONE transaction. Shipped in Agave — and as of 2026-09-06 its enable_tx_v1 gate is active on DEVNET but still has no account on mainnet, so on mainnet 1,232 bytes remains the law.
