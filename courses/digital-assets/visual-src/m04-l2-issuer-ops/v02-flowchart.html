provisioning confidential accounts

two ways to provision, one manual gate

Path A · owner signs every time
owner generates ElGamal keys
owner signs ConfigureAccount + pubkey validity proof
account configured (what the CLI does)
↻  owner signature again, for EVERY account
Path B · registry, sign once
owner registers ElGamal pubkey in a registry account ONCE — one signature, one proof
any caller invokes ConfigureAccountWithRegistry(token, mint, elgamal_registry) — NO owner signature
↻  backends / crons can repeat freely
unapproved until the authority approves — manual policy auto_approve_new_accounts = false → authority runs ApproveConfidentialTransferAccount
account usable
