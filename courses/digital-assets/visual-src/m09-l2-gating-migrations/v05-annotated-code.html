what a distributor’s leaf actually hashes

node = sha256( claimant_pubkey[32] || unlocked_amount_u64_le[8] || locked_amount_u64_le[8] )
leaf = sha256( 0x00 || node[32] )
internal(a, b) = sha256( 0x01 || min(a,b) || max(a,b) )  // pairs sorted by byte value
root = fold internal() up the tree  // an odd node at a level is paired with itself
verify(proof, root, leaf): fold the proof siblings into leaf with internal(), compare to root
source: jito-foundation/distributor — merkle_tree.rs · instructions/new_claim.rs (read 2026-08-22)
the claim itself: who, how much unlocked, how much locked — change any byte and the hash changes
the prefix bytes: 0x00 = leaf, 0x01 = internal. They exist to stop a leaf being read as a node pair — second-preimage resistance for the tree
sorted pairs mean the verifier needs no left/right flags; folding is order-free
the on-chain check: rebuild the root from the proof and compare — agree with this and your root verifies
