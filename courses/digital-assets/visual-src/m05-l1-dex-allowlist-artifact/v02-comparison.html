deriving the rule by elimination

Three guesses that die, one rule that survives

CANDIDATE 1
“refuse anything that changes the amounts”
killed: TransferFeeConfig changes amounts and is ADMITTED
why it survives: the rate is declared in TLV, so pool math can subtract it
CANDIDATE 2
“refuse anything that touches the numbers a UI shows”
killed: InterestBearingConfig and ScaledUiAmount both rewrite the display and are ADMITTED
why they survive: the pool reads raw amounts underneath; the multiplier is decoration
CANDIDATE 3
“refuse anything unaudited”
killed: a well-audited hook program is still REFUSED
partly right: “unreviewed” is Raydium's stated reason for GroupPointer / MemberPointer
SURVIVING RULE
admit extensions that only reshape display or skim a declared fee; refuse extensions that run arbitrary code inside the transfer or move tokens the pool holds
